# AIKOS CRM Intelligence — Речевая и текстовая аналитика

Комплексная система мониторинга, транскрибации, многоуровневого анализа речи (Tone of Voice) и текстовых диалогов клиентов компании AIKOS.

---

## Архитектура системы

```text
    ┌──────────────────────────┐         ┌──────────────────────────┐
    │     incoming/ (Аудио)    │         │     dialog/ (CSV Б24)    │
    └─────────────┬────────────┘         └─────────────┬────────────┘
                  │                                    │
                  ▼                                    ▼
       worker.py (Watchdog)                  dialog_processor.py
                  │                                    │
                  ├─► Google Gemini 2.5 Flash          ▼
                  │   (Транскрибация)         dialogs_data.json / dashboard.html
                  │
                  ├─► ton_voice_processor.py
                  │   ├── Librosa (Акустика: громкость, паузы, темп)
                  │   ├── wav2vec2 (Эмоции по голосу)
                  │   ├── RuBERT (Сантимент реплик)
                  │   └── Gemini (LLM: CSAT, вежливость, чек-листы)
                  │
                  ▼
          PostgreSQL (Docker: 5433)
                  ▲
                  │
        FastAPI Web Server (server.py / app) ──► Frontend SPA (порт 8080)
```

## 5 уровней анализа речи (Tone of Voice)

1. **Уровень 1 (Акустика)**: Анализ громкости (RMS), процента тишины/пауз, пиков и темпа речи через `librosa`.
2. **Уровень 2 (Аудио-эмоции)**: Определение тональности аудио через нейросеть `superb/wav2vec2-base-superb-er` (радость, нейтрально, грусть, раздражение).
3. **Уровень 3 (Посегментный таймлайн)**: Разбивка звонка на синхронизированные реплики с временными метками для веб-плеера.
4. **Уровень 4 (Сантимент текста)**: Анализ эмоциональной окраски каждой фразы клиента и оператора через `blanchefort/rubert-base-cased-sentiment`.
5. **Уровень 5 (Смысловой LLM-анализ)**: Оценка CSAT (удовлетворенности), индекса вежливости, выявление конфликтов и проверка скрипта продаж через Google Gemini API.

## Структура проекта

* `incoming/` — входящие аудиозаписи звонков (`.mp3`, `.wav` и др.).
* `processing/`, `processed/`, `error/` — директории жизненного цикла обработки файлов.
* `transcriptions/` — текстовые расшифровки звонков.
* `dialog/` — выгрузки текстовых диалогов Bitrix24 / WhatsApp (CSV) и генерируемый дашборд.
* `dialog_processor.py` — анализатор текстовых обращений, определения брендов, типоразмеров и исходов.
* `ton_voice_processor.py` — движок 5-уровневого анализа тональности и речевых метрик.
* `worker.py` — фоновый воркер автоматического мониторинга и анализа новых записей.
* `server.py` / `app/` — FastAPI бэкенд (REST API для звонков, аудиостриминг с перемоткой, аудит корректировок).
* `frontend/` — веб-интерфейс аналитики звонков, дашборд качества, профили менеджеров и журнал аудита.
* `docker-compose.yml` — сервисы PostgreSQL (5433), n8n (5678) и web (8080).

## Настройки подключения и окружения

Параметры считываются из переменных окружения или `.env`:
* `DB_HOST` (по умолчанию `127.0.0.1`, в Docker: `postgres`)
* `DB_PORT` (по умолчанию `5433`, внутри Docker: `5432`)
* `DB_NAME` (`company`)
* `DB_USER` (`company_user`)
* `DB_PASSWORD` (`company_password`)
* `GEMINI_API_KEY` — ключ доступа к Google Gemini API
* `PORT` — порт веб-сервера (по умолчанию `8080`)

## Быстрый старт

### 1. Запуск инфраструктуры (Docker)
```powershell
docker compose up -d
```

### 2. Применение миграций БД (при первом запуске)
```powershell
.venv\Scripts\python apply_migrations.py
```

### 3. Запуск фонового воркера речевой аналитики
```powershell
.venv\Scripts\python worker.py
```

### 4. Запуск веб-сервера дашборда
```powershell
.venv\Scripts\python server.py
```
После запуска интерфейс доступен по адресу: **`http://localhost:8080`**  
Документация Swagger UI: **`http://localhost:8080/docs`**

### 5. Анализ текстовых диалогов Bitrix24 (WhatsApp)
```powershell
.venv\Scripts\python dialog_processor.py
```
Для непрерывного мониторинга новых выгрузок CSV:
```powershell
.venv\Scripts\python dialog_processor.py --watch
```

## Версии анализа и эталонный набор (golden set)

После `python apply_migrations.py` каждый анализ звонка сохраняется с провайдером, моделью и версией промпта
(`call_transcriptions.analysis_*`, история — в `call_analysis_runs`). В Gemini отправляется копия аудио
с нейтральным именем файла (без номера телефона).

Проверка качества моделей на звонках, размеченных РОПом:
```powershell
.venv\Scripts\python golden_set.py template --last 150          # CSV для разметки в Excel
.venv\Scripts\python golden_set.py import golden_template.csv --by "Имя РОПа"
.venv\Scripts\python golden_set.py rerun --provider gemini      # проверочный прогон, боевые данные не меняются
.venv\Scripts\python golden_set.py report --details             # точность по полям и чек-листу
```

Что нужно для перехода на локальный сервер и локальные модели — `docs/LOCAL_SERVER.md`.

## Категории звонков

Единый справочник — `call_categories.py`: «Подбор и покупка», «Уточнение по товару», «Заказы и брони», «Сервис»,
«Справка», «Жалоба», «Не клиентский звонок», «Прочее». Категория — тема звонка, итог (бронь/отказ) — в `sale_status`.
Справочник встроен в промпт обоих воркеров, ответ модели приводится к нему при сохранении.
Фильтр и цвета в `frontend/` держать в соответствии со справочником.

Переразметка звонков по справочнику выполнена 01.10.2026 разово; скрипт `reclassify_categories.py`
и отчёт перенесены в `.tech/`. Для повторного запуска (например, после изменения справочника)
скопируйте скрипт обратно в корень проекта: он использует пути и модули корня.
